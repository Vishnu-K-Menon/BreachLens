# DECISIONS.md — Architecture Decision Records

Format: context → decision → consequences. Add new ADRs at the bottom. Never edit an
accepted ADR. Supersede it with a new one.

---
### ADR-001 Single schema of our own design
**Context:** Analyst entry sheets exist in industry, but copying any company's internal
format is inappropriate, and the project targets a data-science role, not data entry.
**Decision:** One wide master schema (`DATA_SCHEMA.md`) with our own snake_case names,
derived from public sources (breach laws, USPS standards, public element lists). Output
views are projections of this one schema.
**Consequences:** No template-mapping layer. A column-mapping config could be added
later if a consumer needs a specific layout.

### ADR-002 Synthetic data only
**Decision:** All people, documents and identifiers come from `synth/` with a fixed
seed. Documents are watermarked.
**Consequences:** OCR accuracy on clean synthetic templates overstates real-world
accuracy. Say so in the limitations.

### ADR-003 No raw sensitive values persisted
**Decision:** Sensitive values exist only in transient `_raw_*` columns. Persist the
present/masked/valid trio plus HMAC-SHA256 keys (salted, truncated to 16 hex
characters) for matching. `leak_guard` blocks any writer that sees an unmasked pattern.
**Consequences:** Entity resolution matches on keys. Reviewers see masked values plus
the source snippet. The exception is ground truth CSVs, which are synthetic and labelled.

### ADR-004 Address verification: US Census Geocoder (primary)
**Context:** RentCast is a property/rental-data API (not an address validator; free
tier 50 req/month). The USPS Addresses API v3 is heavily rate-limited (default 60/hour,
reported in 2026) and moving to paid tiers. Google requires billing. Smarty is a
42-day trial.
**Decision:** The Census batch geocoder (free, no key, ≤ 10,000 rows per batch) is
primary. Geocodio's free tier (2,500/day) is an optional second opinion. The rest are
documented as alternatives.
**Consequences:** Census confirms an address-range match, not USPS deliverability
(no CASS/DPV). Documented as a limitation. Production would use a CASS-certified
service.

### ADR-005 Offline ZIP/city/state check before any API
**Decision:** Use the `zipcodes` package for ZIP validity, ZIP→state and ZIP→city
consistency, with suggestions.
**Consequences:** Catches most typos with zero network calls and works in offline
(on-prem) mode.

### ADR-006 Address pool of verified public buildings
**Context:** Faker street addresses never match a geocoder, so verification would
always fail and the demo would be meaningless.
**Decision:** 80% of synthetic addresses come from a pool of real, public,
non-residential buildings, each verified with Census at build time. 20% are Faker
addresses (expected UNVERIFIED).
**Consequences:** No residential addresses. No privacy concern.

### ADR-007 Label-anchored template extraction, not document-AI models
**Decision:** YAML templates (label regex + direction + value pattern) over
pdfplumber/Tesseract tokens. LayoutLMv3/Donut stay on the roadmap only.
**Consequences:** High precision on known layouts. New layouts need a new YAML. That
fits a 5-day scope and is explainable.

### ADR-008 Presidio as an optional candidate generator
**Context:** Benchmarks report Presidio is high-recall and low-precision (it over-flags).
**Decision:** Use it only on free-text documents (EOB letters) with spaCy
`en_core_web_sm`. All candidates must pass our validators. It is installed via the
`[nlp]` extra.
**Consequences:** The core pipeline has no heavy NLP dependency.

### ADR-009 Rules-based entity resolution first, Splink as a stretch goal
**Context:** Splink (Fellegi-Sunter + EM) is the standard tool, but EM is unstable on
~100 records.
**Decision:** Deterministic key passes plus a weighted rapidfuzz score plus union-find.
Splink comparison is a stretch item.
**Consequences:** Transparent thresholds. The README explains when to switch to Splink
(10k+ records).

### ADR-010 Business rules in YAML config
**Decision:** Rules, jurisdictions, license formats, abbreviations and templates live in
`config/`, validated by pydantic.
**Consequences:** Each engagement or client customization is a config change.

### ADR-011 KNIME as orchestrator with thin Python nodes
**Context:** `.knwf` workflows are GUI artifacts and should not be hand-generated by an
agent.
**Decision:** All logic lives in the `breachlens` package. `knime/nodes/*.py` are thin
wrappers. A human assembles the workflow by following `KNIME_GUIDE.md` and exports the
`.knwf` plus a screenshot.
**Consequences:** One codebase runs from the CLI or from KNIME.

### ADR-012 openpyxl for Excel
**Decision:** openpyxl (read + write, fills, comments, data validation). ZIP and ID-like
columns use the text format.

### ADR-013 Typer CLI, pandas DataFrames, pydantic config
**Decision:** As stated. Stage signature `run(df, ctx) -> df`.

### ADR-014 DuckDB for the SQL layer
**Decision:** Load the output tables into `breachlens.duckdb`. Example queries live in
`sql/queries/`.

### ADR-015 Tesseract OCR + PyMuPDF rasterization
**Decision:** PyMuPDF for rasterizing (no poppler dependency), pytesseract for OCR,
keeping word confidences. If Tesseract is absent, warn and skip scanned documents
(counted in QC).

### ADR-016 Jurisdiction rules are illustrative
**Decision:** 6 states plus a default, each with `verified: false` and a citation.
"Not legal advice" goes in the README and the workbook Summary sheet.

### ADR-017 Public-sources-only design rationale
**Decision:** Every feature must be justifiable from a public source listed in
`DESIGN_RATIONALE.md`. No proprietary or third-party training materials go in the repo.

## Revision 2: scope expansion (two-source pipeline)

### ADR-018 Add a structured-file (Excel/CSV/XLS) input track
**Context:** Breach data arrives as many messy spreadsheets as well as PDFs. The target
role emphasizes cleaning, structuring and feature-engineering this data.
**Decision:** Add a spreadsheet track (`SPREADSHEET_TRACK.md`) that emits the same
`mentions` schema. Reduce the PDF track to 4 types × 2 layouts (~30 docs) to keep the
plan at 6 days.
**Consequences:** Downstream stages are source-agnostic. Cross-source merging becomes a
headline result.

### ADR-019 Column-type classifier is the required ML component
**Context:** A document-type classifier on synthetic forms scores near 100% and proves
little.
**Decision:** The required model is the column-type classifier (engineered value
features + header n-grams), evaluated on unseen header aliases and uninformative
headers. The document classifier (A) and learned matcher (B) are optional.
**Consequences:** The ML result is meaningful and tied to a real data-prep problem.

### ADR-020 XlsxWriter for the workbook; macros embedded from a prebuilt `vbaProject.bin`
**Supersedes:** ADR-012 (openpyxl for writing).
**Decision:** XlsxWriter writes the `.xlsm` (tables, formulas, dynamic arrays, buttons,
VBA via `add_vba_project`). openpyxl only reads reviewer edits. `vbaProject.bin` is
built once by a human from `ReviewHelpers.bas` and committed. Formulas are verified
via a LibreOffice headless recalculation.
**Consequences:** The workbook shows advanced formulas and macros. Results appear only
after Excel/LibreOffice recalculates, which tests handle.

### ADR-021 Cut list
**Supersedes in part:** ADR-004 (Geocodio optional), ADR-008 (Presidio), ADR-009
(Splink stretch).
**Decision:** Do not build Geocodio, Presidio, Splink, the Streamlit review UI, or PDF
types beyond 4. Mention them as alternatives/roadmap in the README.
**Consequences:** About a day of capacity freed for the spreadsheet track, Excel and Ask.

### ADR-022 DuckDB is the system of record
**Supersedes in part:** ADR-014.
**Decision:** All tables, including profiles, mappings, pair features, review decisions,
audit events and run history, persist in `breachlens.duckdb` with declared keys and
`schema_version`. The workbook is a review view.
**Consequences:** Data quality monitoring across runs (`v_quality_trend`) and a stable
handoff contract.

### ADR-023 "Ask BreachLens" text-to-SQL with a local LLM by default
**Decision:**
- Ollama (local) is the default provider and the Claude API is optional.
- The LLM receives only the schema card and the question, never rows (except the
  local-only `--explain` mode).
- Generated SQL passes the sqlglot guard (single SELECT, allow-listed tables, function
  deny-list, LIMIT cap, `_key` columns blocked) and runs read-only.
- Execution accuracy is evaluated on 20 gold questions and 5 adversarial ones.

**Consequences:** It demonstrates applied AI with measurement and on-prem-friendly
privacy.

### ADR-024 FERPA as a flag, not a trigger
**Decision:** Education records (student ID, school) set `ferpa_flag` and add a note.
State triggers stay in `jurisdictions.yaml`. Both are illustrative, not legal advice.

### ADR-025 Engineered matching features are persisted
**Decision:** Every scored pair's features are stored in `pair_features`. This keeps
matching explainable and makes optional model B a drop-in.

### ADR-026 Scale test on generated records
**Decision:** `scale-test` uses 10,000 generated flat records plus the 50,000-row
`large_claims.csv`. It reports rows/sec per stage and peak memory. OCR is excluded
from the scale numbers and its throughput is reported separately.

## Revision 3: read-through findings (2026-10-17)
These ADRs resolve the issues found when the docs were read through before M0. The
affected docs were updated in the same commit. Together they bump `schema_version`
1.0 → 1.1.

### ADR-027 Leak-guard patterns and scope
**Context:** The original SSN-like pattern `\b\d{3}-?\d{2}-?\d{4}\b` matches a ZIP+4
(`12345-6789`), and the account-like pattern `\b\d{9,17}\b` flags harmless numeric
metadata (file sizes, timestamps, digit-only run ids, phone numbers).
**Decision:**
- SSN-like uses one consistent separator: `\b\d{3}([- ]?)\d{2}\1\d{4}\b` (matches
  `123-45-6789`, `123 45 6789`, `123456789`; rejects `12345-6789`).
- The SSN-like and card-like patterns scan every string column except the exempt
  ones. The account-like pattern scans only an explicit list of string columns in config.
- Exempt: numeric/meta columns (`bytes`, `processing_ms`, counts, timestamps such as
  `started_at`/`finished_at`/`processed_at`/`reviewed_at`/`ts`), `*_key`, `zip4`, `phone`.
- `run_id` format: `R%Y%m%d-%H%M%S-xxxx` (4 lowercase hex), e.g. `R20261017-153000-ab12`.
**Consequences:** ZIP+4s and metadata no longer give false positives. A new free-text
column must be added to the account-scan list on purpose.

### ADR-028 Category exposure flags and `notify_required` on `people`
**Context:** The workbook formulas reference `tblPeople[notify_required]` and
`tblPeople[medical_exposed]`. Neither column existed.
**Decision:** Add to `people`: `notify_required` (bool, the same value as in
`notification_list`) and category flags, each the OR of its element flags:
`gov_id_exposed` (ssn, dl, state_id, passport), `financial_exposed` (bank_account,
card), `medical_exposed` (mrn, diagnosis, procedure, date_of_service),
`health_insurance_exposed` (health_member_id, health_group_number),
`education_exposed` (student_id). The formulas in `EXCEL_WORKBOOK.md` stay as written.
**Consequences:** Schema change (part of 1.1). The category flags are redundant with
the element flags by design, for SQL and Excel convenience.

### ADR-029 `doc_date` and address survivorship
**Context:** Survivorship picks "the most recent" address, but no document date existed.
**Decision:** Add `doc_date` (date, nullable) to `inventory` and `mentions`. A mention
inherits its document's `doc_date`. The generator sets it: W-2 → tax-year end
(Dec 31), health claim → date of service, EOB letter → letter date, xlsx/xls →
export date in the file's document properties. CSV files have no document properties,
so their `doc_date` is null. The generator must place planted case P17 (moved address)
in dated sources. Address survivorship: newest `doc_date` (nulls last), then the most
frequent VERIFIED address, then the highest confidence.
**Consequences:** Schema change (part of 1.1). Extraction reads the date from the
document or the file properties.

### ADR-030 Composite keys in DuckDB
**Context:** `breachlens.duckdb` accumulates runs, but `D0001`/`M00001`/`P0001` restart
each run.
**Decision:** Primary keys are composite with `run_id`: `inventory (run_id, doc_id)`,
`mentions (run_id, mention_id)`, `people (run_id, person_id)`, and the same pattern for
every other table. `mentions (run_id, person_id)` → `people (run_id, person_id)` is a
foreign key.
**Consequences:** Every join between tables must include `run_id`. The views and the
Ask layer filter to the latest run unless a query asks for history.

### ADR-031 The scale file lives outside the corpus
**Decision:** `large_claims.csv` (50k rows) is written to `data/raw/scale/`, never to
`data/raw/corpus_v1/`. Only `scale-test` reads it.
**Consequences:** A normal `run` on the corpus never loads the 50k generated records.

### ADR-032 Spreadsheet count: 8 corpus files + 1 scale file
**Decision:** The corpus has 8 spreadsheets. `gt_columns.csv` covers those 8. The
column classifier's hard test set is those 8 plus the uninformative-header columns.
**Consequences:** Wording fixed in `ML_MODELS.md`, `PLAN.md`, `PROJECT_OVERVIEW.md` and
`SYNTHETIC_DATA.md`.

### ADR-033 Ask gold set and few-shot examples are separate
**Decision:** Q01–Q20 are all scored. The four few-shot examples are separate files,
F01–F04 (`sql/fewshot/`), and never appear in the gold set. That makes 24
question/SQL sets in total, each with a snapshot.
**Consequences:** No overlap between the prompt and the evaluation, by construction.

### ADR-034 Column-mapping decision table
**Context:** The original rule didn't cover "rules found no match", "agree but low
probability" or "ML unavailable".
**Decision:** The thresholds are in config (`column_mapping` block):

| rules | ML | decision | outcome |
|---|---|---|---|
| label | same label | `AGREE` | accept; `COL_MAPPING_AGREE_LOW_PROBA` (INFO) if ml_proba < 0.60 |
| none | ml_proba ≥ 0.70 | `ML_ONLY` | accept |
| none | ml_proba < 0.70 | `REVIEW` | `COL_MAPPING_LOW_CONF` (WARN) |
| label | different label, ml_proba ≥ 0.80 | `ML_OVERRIDE` | accept; `COL_MAPPING_ML_OVERRIDE` (WARN) |
| label | different label, ml_proba < 0.80 | `REVIEW` | `COL_MAPPING_LOW_CONF` (WARN) |
| label | unavailable | `RULE_ONLY` | accept |
| none | unavailable | `REVIEW` | `COL_MAPPING_LOW_CONF` (WARN), final_label OTHER |

**Consequences:** Two new reason codes. The `decision` enum gains `ML_ONLY` and
`RULE_ONLY` (part of 1.1). The calibration report must cover 0.60, 0.70 and 0.80.

### ADR-035 ITIN classification runs before SSN validity
**Decision:** A 9xx number in an SSN field is first checked against the ITIN group
ranges. If it matches, only `ITIN_DETECTED` fires and the value goes to
`excluded_identifiers`, so `SSN_AREA_INVALID` does not fire. A 9xx number outside the
ITIN ranges stays an SSN and fails `SSN_AREA_INVALID`.

### ADR-036 Excel date checks use `RunDate`
**Decision:** Every date check in the workbook uses the `RunDate` named range, never
`TODAY()`, so the Excel checks match the Python rules (which use the run date) whenever
the workbook is opened.

### ADR-037 DATA_SCHEMA is authoritative; naming fixes and `audit_events`
**Decision:** `DATA_SCHEMA.md` wins over other docs: `file_profile.header_row` (not
`header_row_detected`), `inventory.bytes` added, `column_mapping.col_idx` and
`reviewed_label` kept. New `audit_events` spec: event_id, run_id, ts, stage,
event_type, item_id, field, code, old_value_masked, new_value_masked, detail_json.
**Consequences:** Schema change (part of 1.1).

### ADR-038 Packaging extras
**Decision:** Core dependencies follow `WORKFLOW.md` (`requests` is core). Extras:
`[dev]` pytest, ruff · `[ocr]` pytesseract · `[ml]` scikit-learn, joblib, matplotlib ·
`[ask]` sqlglot · `[anthropic]` anthropic.

### ADR-039 CLI shape for `evaluate` and `train`
**Decision:** `evaluate [TARGET]`, where TARGET is `pipeline` (default) or `ask`;
`train MODEL`, where MODEL is `column-classifier` (or the optional `match-model`,
`doctype`). Every command in `WORKFLOW.md §Commands` works as written.

### ADR-040 Ask surface and DuckDB hardening
**Decision:**
- Ask only sees views that contain no `*_key` columns: the 6 analytical views plus
  `ask_*` projections of the base tables (`ask_people`, `ask_notification_list`,
  `ask_mentions`, `ask_pair_features`, `ask_column_mapping`, `ask_column_profile`,
  `ask_file_profile`, `ask_inventory`, `ask_excluded_entities`,
  `ask_excluded_identifiers`, `ask_review_decisions`, `ask_runs`). `audit_events` is
  never exposed. Guard rule 5 (`_key` blocked) stays as defense in depth. Q10
  (gray-zone pairs) uses `ask_pair_features`, which contains mention ids, features
  and decisions only.
- Every Ask DuckDB connection is `read_only=True` with
  `config={"enable_external_access": False}`. The 10 s timeout is a timer thread
  calling `con.interrupt()`.
- The adversarial guard tests use canned SQL from a mocked provider, so they are
  deterministic.
**Consequences:** The gold SQL is written against `v_*` / `ask_*` names.

### ADR-041 Excel recalculation and `LET`
**Decision:** `report/recalc.py` runs LibreOffice with its own profile
(`-env:UserInstallation=file:///<tmp>/lo_profile`), set to always recalculate on load,
because XlsxWriter stores no real cached results. A separate profile also avoids the
lock when the LibreOffice GUI is open. `LET` parameter names are written with the
`_xlpm.` prefix (XlsxWriter's `use_future_functions` does not add it).

### ADR-042 Windows development environment
**Decision:** The primary dev machine is Windows 11. `WORKFLOW.md` has a Windows
(PowerShell) block next to the bash one. Paths come from config or env vars, never
hard-coded separators.

### ADR-043 Address pool sourcing
**Decision:** Address-pool candidates are public libraries, city halls and post
offices found by web search. Each one is verified live with the Census one-line
geocoder at build time, and non-matches are dropped. Includes NJ/MA buildings for
the leading-zero ZIPs.

### ADR-044 Leak guard timing and corpus storage
**Decision:** `privacy/leak_guard.py` is built in M4 as planned. Until then, no stage
persists mentions or identifiers to disk; M2/M3 results stay in memory. If an earlier
stage needs to persist, the leak guard is pulled forward first. The generated corpus
`data/raw/corpus_v1/` is git-ignored (deterministic, regenerable). The small committed
`data/raw/sample/` covers tests.

## Revision 4: M1 setup (2026-10-17)

### ADR-045 `synth` is a subpackage of `breachlens`
**Context:** `synth/` sat at the repo root, outside the installed package, so
`breachlens generate` could not import it after `pip install -e .`.
**Decision:** The generators live in `src/breachlens/synth/` (`breachlens.synth`). There
is one installable package.
**Consequences:** `python -m breachlens generate` and `python -m breachlens.synth.*`
work from any directory. The paths in the docs have been updated.

### ADR-046 Pin pandas below 3
**Context:** pip resolved pandas 3.0, which makes string dtype and copy-on-write the
defaults. KNIME's Python integration and several readers are tested against pandas 2.x,
and the spreadsheet track depends on stable `dtype=str` behaviour.
**Decision:** `pandas>=2.2,<3`.
**Consequences:** Upgrading to pandas 3 is a roadmap item, to be done with a dtype audit
of the spreadsheet track.

### ADR-047 Generated-data layout
**Context:** If ground truth or the column-classifier corpus sat in the pipeline's input
directory, `run` would ingest them as breach files (the same trap as ADR-031).
**Decision:**
- `data/raw/corpus_v1/docs/`: the breach input (PDFs + 8 spreadsheets). This is
  `pipeline.yaml paths.input_dir`.
- `data/raw/corpus_v1/truth/`: `gt_mentions.csv`, `gt_people.csv`, `gt_columns.csv`,
  `gt_excluded.csv` (addition: expected EIN/NPI/TIN/ORG exclusions) and `manifest.json`.
  The leak guard excludes this path explicitly.
- `data/raw/column_corpus/`: column-classifier training tables + `labels.csv`.
- `data/raw/scale/`: `large_claims.csv`.
- Only `data/raw/sample/` is committed from `data/raw/`; everything else there is
  regenerable and git-ignored.
- `doc_id` = position (`D0001`…) in the sorted POSIX relative paths under the input
  directory, computed by `breachlens.ingest.doc_ids`. The generator and the inventory
  use the same helper.
- For CSV files, `source_row` is the 1-based physical line number (header and comment
  lines count).
**Consequences:** The commands use `--input data/raw/corpus_v1/docs` and
`--truth data/raw/corpus_v1/truth`.

### ADR-048 Synthetic identifiers are safe by construction
**Decision:**
- Card numbers come only from well-known test IIN prefixes (`411111` Visa test range,
  `555555` Mastercard test range), with random middle digits and a Luhn check digit.
  The planted Luhn failure (P14) changes the check digit only.
- Phones use the fictional `555-01xx` range; emails use the reserved `example.com`,
  `example.org` and `example.net` domains.
- SSNs that land on the known-invalid list are regenerated, except for planted cases.
- Address-pool `source_url`s are the building's official page or the USPS locator,
  never a page that names an individual (staff directories, etc.).
- The README states: "All identifiers are randomly generated; any match to a real
  number is coincidental."

### ADR-049 Address pool: Census ZIPs, reuse cap, shared-address ground truth
**Context:** Checkpoint 1 review of `address_pool.csv` (42 verified buildings).
**Decision:**
- The pool keeps the ZIP that the Census geocoder assigns, even where it differs from
  the USPS ZIP (630 W 5th St, Los Angeles: USPS 90071 → Census 90012; Corpus Christi
  City Hall: 78401 → 78408). The difference is recorded for
  `ASSUMPTIONS_LIMITATIONS.md`.
- `line1` follows the Census standardization where it adds a directional
  (Allentown → `435 W HAMILTON ST`). Oakland stays `125 14TH ST`.
- Buildings named after institutions or donors are allowed. The source-page rule only
  bans pages that list individuals.
- **Reuse cap:** at most 2 *unrelated* households share one pool address
  (`max_unrelated_households_per_address` in `config/synth.yaml`). Planted households
  (dependents, students with guardians, twins) count as one household and are outside
  the cap. The generator asserts the cap.
- Ground truth records every pair of unrelated people who share an address
  (`truth/gt_shared_addresses.csv`), so M5 can report that none of them were merged.
**Consequences:** Unrelated same-address pairs become an explicit over-merge test.

### ADR-050 Expected address status is ground truth; address metrics compare against it
**Context:** By design (ADR-006), about 20% of base households and about 60% of
background extras live on fake streets with a real city and ZIP. With the Census stage
online these are expected to come back UNVERIFIED, so a high UNVERIFIED share is
correct behaviour, not a failure.
**Decision:**
- The generator records `expected_address_status` per mention (`gt_mentions.csv`) and
  per person (`gt_people.csv`), plus `address_source` (POOL / FAKE_STREET). The rule:
  pool building → VERIFIED; fake street → UNVERIFIED; P10 city typo with the right ZIP →
  CORRECTED; P11 ZIP missing a digit → INVALID.
- `manifest.json` records the address mix (pool vs fake street) for base people,
  household members and extras separately, and the expected status distribution for
  mentions and people, overall and by group.
- M5/M7 address metrics report accuracy as agreement with `expected_address_status`
  (per-status confusion matrix), next to the expected distribution. They never use the
  raw VERIFIED share. In offline mode every status is NOT_CHECKED, and the metric is
  reported as "not run".
**Consequences:** UNVERIFIED results on fake streets count as correct. A VERIFIED result
on a fake street counts as an error.

## Revision 5: BreachLens Lite (2026-10-17)

### ADR-051 BreachLens Lite scope
**Context:** The human reduced the remaining scope after M1.
**Decision:**
- M2–M5 are unchanged, except that the M5 scale test times the 50k-row
  `large_claims.csv` only.
- M6: DuckDB load plus 3 views (`v_notify_by_state`, `v_field_error_rates`,
  `v_cross_source_people`) and 5 reference queries. The human writes the `.sql` content
  of `sql/queries/`. The agent creates only the folder, the question headers and the
  snapshot/test harness. `apply-review` is dropped.
- M7: workbook sheets `Summary`, `Mentions`, `Review_Queue`, `People`,
  `Notification_List`, `Excluded`, `About`, with live formulas (`COUNTIFS`,
  `SUMPRODUCT`, `XLOOKUP`, `IF(AND(...))`), conditional formatting and 2 macros
  (`ShowPendingOnly`, `ExportDecisions`). `State_View`, `Formula_Checks`,
  `Column_Mappings` and `File_Profiles` are dropped. The KNIME guide covers the
  spreadsheet track only.
- M8: README, docs and the v1.0 release only. Ask BreachLens moves to Optional.
- Hand-made work that the agent never touches: `notebooks/`, `excel/manual/`,
  `knime/manual/`, `docs/memos/`, and the content of `sql/queries/*.sql`.
**Consequences:** `PLAN.md` lists the dropped items. ADR-033 (F01–F04 few-shot) and
ADR-040 (Ask surface) only apply if Ask is built. `DATABASE_AND_ASK.md` and
`EXCEL_WORKBOOK.md` are read through this ADR.

### ADR-052 Card exposure: present vs trigger vs review
**Context:** Spreadsheets hold pre-masked cards (`XXXX-XXXX-XXXX-1234`), cards destroyed by
scientific notation, and one number that fails Luhn. Not all of these should drive a notice.
**Decision** (illustrative, not legal advice):

| card value | card_present | triggers notice | review |
|---|---|---|---|
| full valid number | Y | yes | no |
| PREMASKED (at most last 4 visible) | Y | **no** (treated as redacted) | no |
| PRECISION_LOST (sci-notation) | Y | yes (most digits exposed) | yes: field stays ERROR `XL_NUMBER_PRECISION_LOST`, person `needs_review` |
| LUHN_FAIL | Y | yes (full number exposed) | yes: field `CARD_LUHN_FAIL` (ERROR), person `needs_review` |

Encoded under `element_rules.card` in `jurisdictions.yaml`. Ground truth: `gt_mentions`
`card_status` includes `LUHN_FAIL`; `gt_people` adds `card_triggers` and `card_review`,
and `notify_required` excludes people whose only card exposure is pre-masked.
**Consequences:** The rule catalogue is unchanged. The limitation is listed for
ASSUMPTIONS_LIMITATIONS.md.

### ADR-053 Fixed `as_of_date`
**Context:** Ages, minor status, DOB plausibility, the 2-digit-year pivot and the
workbook's RunDate depended on "today", so results would drift over time.
**Decision:** `config/pipeline.yaml` has a required `as_of_date` (2026-10-01 for
corpus_v1). It is the single source: the generator reads it (no date in `synth.yaml`),
`Context.as_of_date` carries it through the pipeline, and the workbook's `RunDate` named
range is set to it. `age_at_run` means age at `as_of_date`.
**Consequences:** Re-running a past configuration reproduces its results. Changing
`as_of_date` is an explicit, versioned config change.

### ADR-054 PDF track design: side tables, transient raws, OCR preprocessing
**Context:** M2 needs more than one output table per stage, and the first OCR runs
showed systematic failures on the scans (rows split by rotation, garbled text next to box
borders, titles dropped, border remnants read as text).
**Decision:**
- `Context.tables` holds a stage's side tables (`inventory`, `excluded_identifiers`,
  `excluded_entities`, `pdf_diagnostics`, `pdf_summary`). The stage signature stays
  `run(df, ctx) -> df`, where `df` is `mentions`.
- Extra transient columns: `_raw_group_number`, `_raw_diagnosis`, `_raw_procedure`,
  `_raw_date_of_service`, `_raw_dob` (printed date) and `excluded_identifiers._raw_value`.
  They are masked or dropped in M4 like every `_raw_*` column.
- Text layer: pdfplumber reports the rotated watermark glyphs as upright, so words above
  `text_layer.max_font_size` (30 pt) are dropped instead.
- OCR: deskew (projection profile), binarize at 160, erase box borders (dark runs
  ≥ 80 px), Tesseract psm 11 (psm 6 dropped large titles), and drop words below 0.30
  confidence or 3 pt height. All of these are settings under `ocr:` in `pipeline.yaml`.
- Templates: labels match whole words with optional spaces (OCR merges words), with
  `alt_labels` and a fuzzy fallback for OCR. `boundaries:` lists printed labels that
  bound neighbouring values. `shape`/`charset` repair OCR look-alikes and stray marks.
**Consequences:** Every field failure has a diagnostic status, which the evaluation uses
to explain it. The templates and OCR settings were tuned on corpus_v1's layouts. This
is listed as a limitation: new layouts need new templates (ADR-007), and accuracy on
real scans will be lower (ADR-002).

### ADR-055 Column classifier: broader training data, dev vs test spreadsheets
**Context:** The first trained classifier scored 0.97 macro-F1 on uninformative headers
out-of-fold but only 0.75 on corpus_v1's spreadsheets, with confident wrong labels. The
diagnosis compared feature distributions and found a training/test shift in the
column-corpus generator: no single-format columns (12% mixing was always on), null rate
never 0 or sparse, only simple names (no particles, hyphens, accents, middle initials,
suffixes, `LAST, FIRST` order or uppercase), short org names, one-word categories, long
notes only, and no repeated values.
**Decision:**
- Broaden `synth/column_corpus.py`: name formats and name parts as above, multi-word
  org/school names, short notes and notes with PII, multi-word categories, constant
  columns (4%) and repeated-value pools (26%), pure columns (half), and a null-rate
  mixture (40% complete, 45% 1–40%, 15% sparse 50–95%).
- Because corpus_v1's spreadsheets were inspected during the diagnosis, they become the
  **dev** set (`dev_corpus_v1`). The seed-43 held-out corpus's spreadsheets
  (`data/raw/corpus_holdout`, never inspected before scoring) are the **test** set
  (`test_holdout`). `breachlens train column-classifier --holdout …` scores both, next
  to the out-of-fold uninformative-header columns.
- Nothing is changed because of a holdout result.
**Consequences:** Validation macro-F1 (GroupKFold by alias) drops, because the training
data is harder; spreadsheet scores improve. Limitation: the 8 spreadsheets use the same
header templates in every seed, so the holdout tests new values under known layouts.
The header-blind test is the uninformative-header set.

### ADR-056 Mapping: OTHER never overrides a rule label; rule keyword order
**Context:** ADR-034 lets ML override a rule label at p ≥ 0.80. On the dev set the
classifier predicted OTHER for the wide dependent columns (`Dep3_DOB`, `Dep3_First`) and
a plain `DOB` column at p > 0.9. Disclosure: this error list was first printed for the
test set (`test_holdout`). The dev set shows the identical nine errors, so the fix holds
on dev alone, but the test set is no longer strictly unseen for this rule. Separately,
the merged header `Home Address State` matched the `address` keyword before `state`.
That was found on a dev-set run with a small model.
**Decision:**
- OTHER means "no recognized type", so it never overrides a concrete rule label: rules
  label + ML OTHER → `RULE_ONLY`, rule label kept. This is a new row in the ADR-034 table.
- In `header_aliases.yaml`, `city` and `state` are checked before `street`/`address`,
  as `zip` already was.
**Consequences:** ML still overrides one concrete label with another (e.g. `Insurer`
ORG_NAME → SCHOOL at 0.83 on the dev set, a known wrong override that is reported, not
patched). The rules baseline now fails only on `ID` and `Column7`, which it cannot
recover by design.

### ADR-057 Spreadsheet track outputs, model files, olefile
**Decision:**
- Side tables in `Context.tables` (ADR-054): `file_profile`, `column_profile`,
  `column_mapping` (+ `codes`), `sheet_codes`, `sheet_summary`. Organizations and EINs
  from sheets are appended to `excluded_entities` / `excluded_identifiers`.
- Row-level reason codes travel in the transient `_repair_codes` column until the M4
  validation engine; card/SSN status in `_card_status` / `_ssn_status`.
- Duplicate rows in a file are kept once, and the original row gets
  `ROW_DUPLICATE_IN_FILE` (P42). Excel error cells anywhere in a row are nulled, and the
  row gets `XL_ERROR_VALUE` (P43). A long ID stored as a number with 16 or more digits
  is `XL_NUMBER_PRECISION_LOST`, because Excel keeps 15 significant digits (P33).
- `models/column_classifier.joblib` is git-ignored: it is regenerated by
  `breachlens train column-classifier` (about 2.5 minutes). The model card, metrics
  JSON and plots are committed. These hold headers, labels and probabilities, never cell
  values. Without a model the stage runs rules-only (`RULE_ONLY`) and logs a warning.
- New dependency `olefile` reads the `.xls` creation date for `doc_date`.
- New config: `models_dir` in `pipeline.yaml`.

### ADR-058 M4 outputs, the guarded writer and the leak-guard test corpus
**Context:** M4 is the first milestone that writes outputs. DuckDB arrives in M6 and the
workbook in M7. PRIVACY.md §4 had the leak test run on `data/raw/sample/`, which is
empty and would need its own subset of ground truth.
**Decision:**
- Each run writes CSV tables to `data/output/<run_id>/`: `mentions`, `inventory`,
  `excluded_entities`, `excluded_identifiers`, `doc_codes`, `file_profile`,
  `column_profile`, `column_mapping`. It also writes `audit_<run_id>.jsonl` and a
  counts-only `run_summary.json`. CSV needs no new dependency and KNIME reads it.
  `pdf_diagnostics` stays in memory.
- `privacy/writer.py` is the only write path in the package, and M6/M7 reuse it. A run is
  scanned completely before anything is written, and any finding means no file is
  written. Writing is refused if the privacy stage is disabled.
- `python -m breachlens.privacy.leak_guard <dir>` scans a written directory. It is
  column-aware for CSV/JSONL and lists every file with its finding count.
- `tests/test_leak_guard.py` generates a reduced corpus in tmp (both tracks: text PDFs,
  scans, 8 spreadsheets), runs the full pipeline with writes, scans every output file,
  and checks that no raw ground-truth identifier appears in any output byte.
  `data/raw/sample/` is not used.
- The offline ZIP check (`address/zipcheck.py`, `zipcodes`) moves from M5 into M4,
  because ADDR_ZIP_STATE/CITY_MISMATCH are validation rules and P10 needs them. Census
  stays in M5.
- M4 address status is INVALID (unfixable state/ZIP) or NOT_CHECKED, with
  `address_suggestion` set. The full status mapping (VERIFIED / CORRECTED / UNVERIFIED)
  needs Census and is applied in M5.

### ADR-059 Rule engine: one severity source, code scopes, column codes on mentions
**Decision:**
- `config/rules.yaml` declares every reason code with `severity`, `stage`, `scope`
  (mention / doc / column / excluded) and `milestone`. The engine assigns severities
  only from there, and an undeclared code is an error. M2/M3 producers keep emitting
  bare codes.
- `qc_status` is FAIL if any ERROR, REVIEW if any WARN, else PASS. `review_status` is
  PENDING unless PASS.
- `sheet_codes` is renamed `doc_codes` (+ `severity`), because DOC_TYPE_UNKNOWN is
  doc-level too.
- Column-level WARN codes (COL_MAPPING_LOW_CONF, COL_MAPPING_ML_OVERRIDE,
  COL_UNMAPPED_SENSITIVE) are copied to every mention that took a non-empty value from
  that column. Wide dependent columns go to dependents only, and guardian columns to
  guardians only. A reviewer then sees the uncertainty on the person it affects; one
  column decision clears them all (M7).
  - Consequence: the known `Insurer` → SCHOOL override (ADR-056) puts those patient
    mentions in REVIEW. It also sets `ferpa_flag` on them through FERPA_RECORD. This is
    reported, not patched.
- Exclusion codes lead the `reason` of `excluded_*` rows. PROVIDER_TIN uses
  EIN_EXCLUDED, since it has the same format and no separate code exists.
- Small calls:
  - Street lines are kept as printed, upper-cased (the ground truth keeps unabbreviated
    suffixes); only units are standardized.
  - ADDR_MISSING is skipped for mentions linked to a household mention (dependents,
    guardians).
  - NAME_SUFFIX_INVALID keeps the printed suffix; the suggestion goes in the audit
    detail.
  - LOW_OCR_CONFIDENCE applies to OCR mentions only.
  - NAME_VARIANT_IN_DOC compares mentions with the same SSN in one document.

### ADR-060 Masking, HMAC keys and exposure from notes
**Decision:**
- Masks keep the last 4 characters: `***-**-1234` for SSNs, `*`×(n−4)+last 4 for other
  IDs. Pre-masked values keep their own mask.
- `*_key` = first 16 hex characters of HMAC-SHA256(salt, `KIND:value`), with
  `SSN:<9 digits>`, `DL:<state>:<number>`, `PASSPORT:<country>:<number>`. The kind
  prefix keeps equal digits of different kinds apart. Pre-masked and precision-lost
  values get no key.
- `<e>_valid` is PASS, the element's first reason code (including PREMASKED_VALUE /
  XL_NUMBER_PRECISION_LOST), or null when absent.
- An SSN, MRN or card found in a notes column counts as an exposed element of that row's
  person (`*_present`, masked, keyed), next to FREE_TEXT_PII_FOUND.
- Free-text masking hides every run of 9+ digits, phone numbers included.

### ADR-063 Census batch geocoder, cache-first and offline by default
**Context:** M5 verifies addresses with the Census batch geocoder. The project owner
allows network for this alone, opt-in, keeping `offline: true` as the pipeline default
(the on-prem story).
**Decision:**
- `address/census.py` adds a batch client: POST `/geocoder/locations/addressbatch`,
  `benchmark=Public_AR_Current`, at most 10,000 rows per request. Only street line 1
  (without the unit), city, state and ZIP are sent.
- One cache entry per address (`data/cache/census/<sha256>.json`). Only cache misses are
  sent, so a later run with a different address set re-sends nothing that's cached.
- `offline: true` stays the default. Offline runs read cached results, and addresses
  with no cache entry are NOT_CHECKED. `breachlens run --online` is the explicit opt-in
  that fills the cache; it is the only network path in the code base. Tests use a
  recorded response and never call the service.
- Status mapping: VALIDATION_RULES.md, plus one addition. A `Match` + `Non_Exact`
  result counts as CORRECTED only if it keeps the house number and the street
  (token-sort ≥ 95) and the ZIP or the city. The first live probe showed the geocoder
  snapping a fake street to a real one nearby (4603 ANDERSON KEYS 32825 → 4603
  ANDERSON RD 32812). A rejected Non_Exact match is UNVERIFIED + ADDR_GEOCODE_NOMATCH.
- The scale test never calls Census (cache only).
**Consequences** (corpus_v1): mention status agreement with `expected_address_status` is
396/398. Both misses are one pool address (125 14TH ST, Oakland). The oneline geocoder
matched it in M1. The batch geocoder returns Match + Non_Exact "125 14TH" with the
street type dropped, which this rule rejects (street similarity 84 < 95), so the
mentions are UNVERIFIED + ADDR_GEOCODE_NOMATCH. Corrected 2026-10-18: earlier notes
said No_Match. Reported, not patched. A follow-up could compare streets without their
type or retry with the single-line lookup.

### ADR-064 Matching details
**Decision** (on top of ARCHITECTURE.md §resolve; settings in `config/matching.yaml`):
- Runs after privacy, on HMAC keys and normalized fields only.
- Pass C re-weights over the features present (null features drop out).
- A pair with no DOB, ZIP or address evidence is capped at 0.89 (REVIEW, NAME_ONLY): a
  name alone never merges.
- DOB conflict (both present, `f_dob` ≤ 0.3) caps the score at 0.69. Day-month
  transpositions (0.7) are not conflicts.
- Never merged:
  - both `ssn_key` present and different. These pairs are counted but not scored or
    stored, which keeps the 50k run at 7 s and under 1 GB.
  - two mentions on the same source row (subscriber/dependent)
  - mentions linked by `related_mention_id`
- Cluster-level cannot-link: union-find never joins clusters whose SSN keys or DOBs
  conflict, so a no-SSN/no-DOB row cannot bridge twins.
- Names are compared accent-folded (JOSÉ = JOSE) with nickname expansion
  (`config/nicknames.csv`); the soundex key is accent-folded too.
- REVIEW pairs across clusters → DUPLICATE_CANDIDATE. A same-SSN DOB conflict →
  DOB_CONFLICT_IN_CLUSTER. `people.needs_review` = a card PRECISION_LOST / LUHN_FAIL
  or either code.
